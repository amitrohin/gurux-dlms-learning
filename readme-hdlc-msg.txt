1. ОБЩАЯ СХЕМА УРОВНЕЙ (СНИЗУ ВВЕРХ)
Поток байтов (fp)
-> HDLC_READER  : выделяет один физический кадр [0x7E .. 0x7E], проверяет CRC.
-> HDLC_FRAME   : чистый MAC-кадр (адреса, Control, fragment_bit, сырой info).
-> HDLC_SESSION : маршрутизация по паре <Client_Addr, Server_Addr>, окно N(S)/N(R).
-> HDLC_MSG     : сборка сегментов I-frame, разбор LLC (3 байта), выдача APDU.
-> COSEM APDU   : прикладной уровень (AARQ, Get, Action, Push и др.).
2. СПЕЦИФИКА СПОДЭС И ПРАВИЛА ПРОТОКОЛА
• Сегментация (fragment_bit = S, маска 0x08 в 1-м байте Format):
	• Разрешена ТОЛЬКО для информационных кадров I-frame.
	• S-frame (RR, RNR) и U-frame (включая UI) НИКОГДА не сегментируются (S = 0).
• Размер окна (window_size_transmit / receive):
	• По умолчанию 1, но при согласовании SNRM/UA допускается от 1 до 7.
	• Между сегментами I-frame могут приходить S-frame (RR) подтверждения.
• Подзаголовок LLC (3 байта: E6 E6 00 от клиента, E6 E7 00 от сервера):
	• Есть ТОЛЬКО в первом (или единственном) I-frame цепочки и в кадрах UI.
	• Во 2-м, 3-м и далее сегментах I-frame заголовок LLC ОТСУТСТВУЕТ.
	• В S-frame и управляющих U-frame (SNRM, UA, DISC, DM, FRMR) LLC ОТСУТСТВУЕТ.
• Бит P/F (0x10 в поле Control):
	• От клиента (P): 1 = передача права ответа серверу, 0 = ответ не нужен.
	• От сервера (F): 1 = завершение ответа, возврат управления клиенту.
	• В инициативном выходе счетчика (UI / Push): работает как P (1 = нужно
подтверждение доставки от сервера сбора данных, 0 = без подтверждения).
• Несколько соединений на одном канале:
	• Физический кадр в линии не прерывается другим кадром (один HDLC_READER).
	• Одновременно могут жить несколько сессий с разными счетчиками или разными
Client SAP (0x10, 0x20, 0x30) к одному счетчику.
	• Сборка сегментов и счетчики N(S)/N(R) ведутся раздельно для каждой сессии.
3. ОТВЕТСТВЕННОСТЬ МОДУЛЕЙ
[HDLC_FRAME] (MAC-подуровень)
• Поля: nref, mbuf frame, length, DA (upper/lower), SA (upper/lower),
fragment_bit, control (I/S/U), info_offset, info_len.
• Не знает про LLC, списки цепочек и состояние сессии.
• В HDLC_fini() обязательно освобождает mbuf_fini(&frame->frame).
[HDLC_READER] (бывший HDLC_CTX — автомат чтения одного кадра)
• Один экземпляр на физический порт/дескриптор (fp).
• Состояния: Initial -> FrameOpenFlag -> FrameFormat_1 -> FrameFormat ->
DA[_1..3] -> SA[1..3] -> Control -> HCS_1 -> HCS -> [Info -> Info] ->
FCS_1 -> FCS -> Complete.
• Состояния HDLC_LLC_* из автомата убираются: любой кадр с полезной нагрузкой
читается единообразно до FCS_1 -> FCS (проверка CRC-16/X.25) -> Complete.
• После Complete возвращает готовый HDLC_FRAME* наверх и сбрасывается в Initial.
[HDLC_MSG] (LLC-подуровень и сборка фрагментов)
• Владеет кольцевым списком/очередью из одного или нескольких HDLC_FRAME.
• Хранит: nref, список кадров, has_llc, llc_dsap, llc_ssap, llc_control,
общую длину чистого APDU (apdu_len).
• При добавлении 1-го кадра:
	• Если I-frame или UI-frame: проверяет наличие >= 3 байт info, извлекает LLC
(0xE6, 0xE6/0xE7, 0x00), выставляет has_llc = 1, сдвигает начало APDU на +3.
	• Иначе (SNRM, UA и др.): has_llc = 0, данные берутся с info_offset.
• При добавлении 2-го и последующих кадров:
	• Проверяет совпадение (DA, SA), тип HDLC_I, последовательность N(S) и флаг
fragment_bit == 1 у предыдущего кадра.
	• Весь info_len фрагмента целиком добавляется к APDU (без сдвига на LLC).
• Готовность сообщения: у последнего добавленного кадра fragment_bit == 0.
• В HDLC_MSG_fini() в цикле вызывает HDLC_FRAME_detach() для всех кадров.
[HDLC_SESSION] (Управление логическим каналом <Client_Addr, Server_Addr>)
• Идентифицируется канонической парой адресов клиента и сервера (учитывая,
что в запросе SA=Client, DA=Server, а в ответе SA=Server, DA=Client).
• Хранит: адреса, состояние (DISCONNECTED / CONNECTED), переменные окна vs (N(S))
и vr (N(R)), согласованные параметры окна/длины, текущую сборку HDLC_MSG *rx.
• Обработка входящего HDLC_FRAME:
	• I-frame -> добавляет в session->rx:
		• если fragment_bit == 1 и pf == 1: формирует ответный S-frame RR(vr);
		• если fragment_bit == 0: отдает завершенный HDLC_MSG на уровень COSEM
и обнуляет session->rx.
	• S-frame (RR/RNR) -> обновляет состояние окна отправки и подтверждений.
	• SNRM / UA / DISC / DM -> меняет состояние соединения, сбрасывает vs, vr, rx.
	• UI-frame -> не требует сессии, сразу оборачивается в 1-кадровый HDLC_MSG.
4. СПИСОК ПРАВОК ИЗ РЕВЬЮ ПЕРВОГО ПРОТОТИПА (НЕ ЗАБЫТЬ)
• Вызывать mbuf_fini(&hdlc->frame) при освобождении кадра.
• В HDLC_CTX_fini() / HDLC_MSG_fini() освобождать все узлы кольца, а не только 1-й.
• Следить за локальным указателем hdlc вместо ctx->hdlc при разборе заголовка.
• Учесть граничный случай пустого APDU при наличии LLC (payload_len == 3).
• Учитывать особенности feof(fp) на неблокирующих дескрипторах / termios VTIME.
